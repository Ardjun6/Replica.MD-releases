# ReplicaMD beta session

Allow about 30 minutes. Use a disposable repository and notes; keep a backup of
important work. Record the app version, OS, architecture and installer type.
Do not send provider keys, tokens, personal calendars, or private backups.

1. Download and install the release. Record security prompts and launch errors.
2. Create a local profile without connecting Google. Can you explain what the
   app does and find the next action without help?
3. Confirm Git and your chosen agent CLI are installed and authenticated.
   Windows requires Git for Windows/Git Bash. Provider usage is billed by the
   provider; use a small task within your allowance.
4. Add the disposable project. Open its terminal, run `pwd` (Git Bash on
   Windows), and check it matches the selected folder.
5. Start one configured agent. Ask it to create a small README in the disposable
   repository. Confirm the file exists and inspect the changes.
6. Quit and reopen ReplicaMD. Confirm project, file and session recovery, then
   stop the test agent. Record whether anything was lost or duplicated.
7. In Knowledge, create a note, edit it, add a harmless attachment, move the
   note and export it. Reopen and check note and attachment content.
8. Create a second local profile. Confirm each profile's Logboek is independent.
   Add a fixture entry; export/import the profile into a fresh app home and
   confirm the entry after restart. Profile backups do not include project files.
9. Back up the Knowledge vault to a folder outside its source. Restore into a
   fresh folder and verify note content and attachment bytes.
10. Open Help and support. Report one confusing step or problem using the public
    tracker: https://github.com/Ardjun6/Replica.MD-releases/issues.

## Feedback

- Version / OS / installer:
- Did you complete the first task? Where did you need help?
- What did you expect, and what happened?
- Reproduction steps:
- Was any work lost? What recovery worked?
- Would you use this for another task? Why?

## Owner process

Recruit 5–10 consenting testers across native Windows and Linux. Give each the
same release and script. Record completion, blockers and feedback, with no
invented results. Resolve installation, lost-work and core-task blockers before
expanding the audience. Keep personal contact details outside source control.
